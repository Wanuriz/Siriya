# AGENTS.md - SIRIYA

Обязательные правила для любого агента: ZCode, субагенты, плагины. Читай первым.
Если правило мешает работать, остановись и запиши причину в `docs/BLOCKERS.md`. Обход молча запрещён, честная остановка лучше.

Проект: нарративная 2D-игра на Godot 4.7.2 (GDScript), пиксель-арт, ходьба по локациям, диалоги и выборы. Контекст: `docs/PROJECT_CONTEXT.md`.

## 0. Начало каждой сессии

1. Прочитай по порядку: этот файл, `docs/STATUS.md`, `docs/CANON_CHEATSHEET.md`. По необходимости: `docs/DECISIONS.md`, `docs/BLOCKERS.md`, `docs/PROPOSALS.md` и три свода (`docs/lore_bible_part_A.md`, `docs/game_bible_part_B.md`, `docs/story_scenario_part_C.md`).
2. Выполни `git status` и `git log --oneline -5`.
3. Выполни `python tools/check.py` и покажи итог. Если там красное, оставшееся с прошлых сессий, не чини молча, сообщи.
4. Скажи в двух фразах, что понял и какой следующий шаг. Жди подтверждения, если руководитель не написал «работай автономно».

## 1. Люди и роли

- **Руководитель проекта** решает окончательно. Без его слова [у] ничего каноничного не добавляется.
- **Ты (ZCode + GLM)** реализуешь в Godot: код, данные, тесты, импорт арта. Общаешься с руководителем по-русски; код, имена файлов и комментарии на английском; видимые игроку тексты на русском.
- Сюжет, диалоги и названия приходят от руководителя (иногда через чат с другим ассистентом) и вставляются как есть.

## 2. Канон и тексты: главное правило проекта

- Источники истины: три свода и исходные тексты в `docs/`. Короткая сверка: `docs/CANON_CHEATSHEET.md`. Чек-лист приёмки: `docs/CANON_CHECKLIST.md`.
- Пометки: **[к]** канон из источников, **[у]** утверждено руководителем, **[п]** предложение (не канон), **[с]** решение, которое ты принял сам из-за отсутствия решения (запиши в `docs/DECISIONS.md`: вопрос, вариант, где переключается данными).
- **Ты не сочиняешь сюжет, имена, факты мира и реплики.** Нужен текст, а его нет: поставь заглушку `TODO_TEXT: <id>` и добавь строку в раздел «Нужны тексты» в `docs/STATUS.md`. Разрешено раскладывать по данным текст, который уже есть в сводах или пришёл от руководителя.
- В данных (`data/**.json`) каждая текстовая единица имеет поле `"src"` со значением `"к"`, `"у"` или `"п"` и, по возможности, `"ref"` (источник: «И5», «часть С, гл. 2», «руководитель, дата»). Так [п] не превратится в канон незаметно.
- **Загадки не разрешать** (список в памятке: Хасан, чей Имаад, кто взял мопеды, Улитка, плёнка, Иблис, чертог и другие).
- Декор, живность, безымянные жители: [п], без имён, сюжета и лора.
- **Не добавлять** крафт, инвентарь, биомы, бой, копание, постройку блоков. Любая идея вне сводов: строка в `docs/PROPOSALS.md`, не в игру.
- Тон: абсурдная сатира, юмор в ситуациях и предметах, не во внешности людей; без карикатур на народы и религию.

## 3. Три уровня работы: сколько ритуала нужно

Выбери уровень до начала и назови его в первом сообщении. Сомневаешься: бери уровень выше.

| Уровень | Что это | Обязательно |
|---|---|---|
| **Малый** | правка в одной системе до ~100 строк, импорт арта, правка данных без сюжетного текста | запуск проекта через Godot MCP: консоль без ошибок; `python tools/check.py` |
| **Фича** | новая сцена, система или механика; любая правка логики состояния | короткий план (ecc:planner для нетривиального); скилы из п.5; тест для критичной логики (ecc:tdd-guide); godot-reviewer; playtester; `check.py` |
| **Веха** | глава или локация целиком; смена контрактов между системами; перед релизом | всё из «Фичи» + ecc:architect при смене контрактов + ecc:code-reviewer на всю дельту + game-designer на видимые тексты + ecc:doc-updater + запись в `STATUS.md` |

**Критичная логика** (всегда с тестом до реализации): счётчик плодов и пять дверей, голос Улитки, исход 8.4 (16 строк), перебор вариантов плодов, концовки и три перечня Летописца, сохранение и загрузка.

## 4. Субагенты

«Вызвать» значит реально запустить как инструмент, а не написать имя в тексте. Задание субагенту нейтральное, без подсказок вроде «проверь только X». Независимое запускай параллельно, зависимое по очереди.

| Агент | Когда | Ограничения |
|---|---|---|
| `ecc:planner` | старт вехи или нетривиальной фичи | план 10-20 строк с критериями готовности; для вехи сохранить в `docs/plans/<имя>.md` |
| `ecc:architect` | новая система или смена контрактов (GameState, диалоги, сохранения, переходы между локациями) | решение записать в `docs/ARCHITECTURE.md` |
| `ecc:tdd-guide` | критичная логика (см. п.3) | сначала падающий тест, потом код |
| `ecc:docs-lookup` | API Godot 4.7, в котором нет уверенности | по памяти API не угадывать. Если субагент не стартует (MCP context7 недоступен), прочитай официальную документацию docs.godotengine.org (раздел 4.7) главной сессией и пометь «api подтверждён документацией» |
| `ecc:build-error-resolver` | ошибки парсинга, импорта, запуска | чинить причину, не заглушать |
| `godot-reviewer` | после законченной фичи (.gd, .tscn, .tres, data), до коммита | |
| `ecc:code-reviewer` | на вехе, на всю дельту | |
| `playtester` | после фичи: реальный запуск через Godot MCP, консоль, walk-тест | не писать «прошёл» без скриптового ввода (см. п.6) |
| `game-designer` | проверка видимого текста на канон (сверка с чек-листом); раскладка текстов сводов по данным | **не выдумывает** сюжет и реплики |
| `pixel-art-tiles` | только спрайты и тайлы персонажей и объектов, по одному ассету за вызов | фоны локаций делает руководитель в ChatGPT/Gemini, импорт: `tools/art/import_bg.py`; вызов упал по таймауту (600 с): раздели задачу, не повторяй то же |
| `ecc:doc-updater` | конец вехи | |
| `ecc:refactor-cleaner` | перед релизом | контракты не трогать |
| `ecc:security-reviewer` | один раз после сохранения/загрузки и скриптов в `tools/` | |

Прочее:
- Агентов ECC, не перечисленных выше, не вызывать.
- Агент недоступен или вернул ошибку: не заменяй его молча своей работой. Запиши в `docs/BLOCKERS.md` и сообщи руководителю.
- Не больше 2 кругов исправлений по ревью на фичу. Остаток P0/P1 после второго круга: остановись и доложи.
- Исправление ошибки уровня P1 начинай с теста, который падает на старом коде.
- Отчёты ревьюеров не править. После правки проверенных файлов нужен новый прогон по изменённым файлам.

## 5. Скилы

Перед первым кодом сессии прочитай `SKILL.md` нужных скилов:
- код: `godot`, `godot-gdscript-patterns`, `godot-best-practices`;
- арт и анимации: `godot-2d`; интерфейс: `ui-ux`;
- ECC: `tdd-workflow` (вместе с tdd-guide), `search-first` (прежде чем писать новое, проверь, нет ли готового в проекте или в Godot), `verification-loop` (конец вехи), `strategic-compact` (длинная сессия), `security-review`.

## 6. MCP, плагины, инструменты

- **Godot MCP:** запуск проекта, вывод консоли, ошибки. **Ввода (клавиши, мышь) у него нет.** Интерактив проверяй скриптовыми тестами (`tests/walk_*.gd`), а не словами «проверил руками».
- **context7** (если подключён): прямые вызовы главной сессии для документации. Субагенты видят новый MCP только после перезапуска ZCode.
- **ECC и его хуки (GateGuard)** не менять. GateGuard перед первой правкой просит фактов: отвечай кратко, не обходи.
- Новые MCP, плагины, аддоны Godot, пакеты: только с разрешения руководителя. Не скачивать чужой код и ассеты. Ассеты: свои, CC0 или OFL, с записью в `LICENSES.md`.
- Работай только внутри папки проекта. Без `git push`, force, `--no-verify`.

## 7. Проверка и доказательства

- Одна команда: `python tools/check.py` (канон-линт текстов + Godot-тесты в headless). Ошибки (`ERROR`) чинить, предупреждения (`warn`) прочитать и ответить в отчёте. `INCOMPLETE` не считается зелёным.
- Доказательство = вывод команды или содержимое файла. «Готово», «зелёно», «исправлено» без вывода запрещены. Пиши «не проверено».
- Тесты и правила линта не ослаблять (не удалять проверки, не расширять допуски). Если нужно, запись в `docs/DECISIONS.md` с причиной.
- Тесты, ждущие кадров (скриншоты, замеры FPS), зависают в headless: запускай только окном.
- Тесты пиши в `tests/test_*.gd`, при успехе печатай маркер вида `STATE_TESTS_OK` (его ищет `check.py`).

## 8. Файлы и git

- Файлы правь инструментами Edit/Write. Python- или sed-патчи `.gd` через shell запрещены. Временные скрипты удаляй.
- Коммиты небольшие и по смыслу. Перед коммитом: `check.py`, `git diff project.godot` (изменения от `--import` не коммитить без причины).
- Процесс (AGENTS.md, `tools/`) и игру коммить отдельно; у процессных коммитов префикс `process:`.
- Путь проекта только латиницей, без пробелов. Скриншоты и рендеры: максимум две последние версии (на диске мало места).
- Движок и инструменты: Godot 4.7.2; `.godot/` в `.gitignore`.

## 9. Документы процесса (короткие)

- `docs/STATUS.md`: состояние, следующий шаг, «Нужны тексты», журнал. Обновляй после каждого блока работы.
- `docs/DECISIONS.md`: [с]-решения. `docs/BLOCKERS.md`: что остановило и что нужно от руководителя. `docs/PROPOSALS.md`: все [п].
- `docs/ARCHITECTURE.md` создаёшь на первой фиче, обновляешь по ходу.

## 10. Формат отчёта (короткий)

1. **Сделано** (файлы).
2. **Проверено** (вывод команд).
3. **Не проверено** и почему.
4. **Агенты:** имя, задача, главный вывод. Не вызывал: так и пиши, с причиной.
5. **Решения [с]** и **нужны тексты**.
6. **Вопросы** (не больше одного; в автономном режиме не задавай, бери [п]-дефолт и запиши в DECISIONS).

## 11. Запрещено

Ослаблять тесты и линт без записи; править отчёты ревьюеров; ставить PASS без запуска; писать «вызвал агента» без вызова; выдавать [п] за канон; выдумывать имена, лор, связи персонажей; разрешать загадки; расширять объём сверх задания; править файлы после ревью без нового ревью; переписывать историю git.

**Аварийная остановка:** нужный агент или MCP недоступен без обходного пути; нет места на диске (меньше 2 ГБ); P0/P1 после двух кругов; красные или нестабильные тесты по неустранимой причине; контекст на исходе посреди работы. Сломанное не коммить, запиши точное состояние в `STATUS.md` и `BLOCKERS.md`, дай итог.
