# ARCHITECTURE - SIRIYA, контракт первого среза

Контрактный документ (автор текста: ecc:architect, 2026-11-12). Меняется только через новый прогон по изменённым системам и запись в журнале `docs/STATUS.md`. Принципы: `docs/PROJECT_CONTEXT.md` раздел 4 (данные отдельно от кода, signal-up/call-down).

## 1. Карта модулей (первый срез)

```
scripts/game_state.gd      autoload GameState (единственное глобальное состояние)
scenes/locations/bazaar.tscn   локация: фон Sprite2D + игрок + debug-метка
scenes/locations/oasis.tscn    аналогично
scenes/characters/player.tscn  общая заглушка игрока (цветной прямоугольник)
assets/backgrounds/*.png       480x270, Nearest
```

Направление зависимостей: сцены и скрипты локаций НЕ ссылаются на GameState. GameState ни на что не ссылается. Связь «локация -> GameState» появится только у будущего диалогового рана.

## 2. Контракт GameState (res://scripts/game_state.gd, extends Node)

Только эти пять методов. Ничего не добавлять без смены контракта (см. п.6).

```gdscript
func set_flag(flag_name: String, value: bool) -> void
func get_flag(flag_name: String) -> bool    # несуществующий флаг = false
func has_flag(flag_name: String) -> bool
func set_fruits(count: int) -> void         # clamp 0..3
func get_fruits() -> int                    # старт 0
```

- Внутри: `Dictionary` флагов и `int` счётчик плодов. Без сигналов, без ссылок на узлы, без сериализации.
- Имена флагов берутся из словаря состояний части С, раздел 0.3; GameState их не знает (тупое хранилище).

## 3. Контракт переключения локаций

- Клавиши: F1 открывает базар, F2 открывает оазис. На первом срезе без InputMap: код клавиши сравнивается напрямую (KEY_F1 / KEY_F2) в `_unhandled_input`.
- Обработка: общий минимальный скрипт `scripts/location.gd` на корне каждой локации, соответствие «клавиша -> путь сцены» — константа скрипта. Никакого менеджера локаций, пока локаций мало.
- Переход: `get_tree().change_scene_to_file("res://scenes/locations/<имя>.tscn")`. Только эти два пути; строка пути не конкатенируется из частей. Повторное нажатие клавиши текущей локации — no-op.
- Игрок — инстанс `player.tscn` внутри каждой локации; позиция между локациями НЕ переносится (сознательно: нет сохранения координат).
- GameState переживает переключение сам по себе как autoload — локации о нём не знают.

## 6. Как расширяется

1. Диалоги: JSON в `data/dialogue/`, каждая реплика с полем `src` («к»/«у»/«п») и, по возможности, `ref`; команды реплики могут вызывать `GameState.set_flag` / `set_fruits`. Ран — отдельный узел/скрипт, GameState остаётся тупым.
2. Сохранение: сериализация словаря флагов и счётчика в JSON; загрузка — обратное заполнение. GameState получает только `to_dict()`/`from_dict()` (это будет смена контракта — ecc:architect + запись здесь).
3. Больше локаций: при 4+ локациях или переходах не по F-клавишам — выделить менеджер переходов (контракт из п.3 заменяется).
